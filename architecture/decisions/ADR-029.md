# ADR-029: Name malformed table rows deterministically; ground judge objections

Status: accepted (post-disclosure, after run 21). Part of the same harness identity as ADR-028.

## Context
Run 21 (45540758298, #39) failed the A1 semantic validation twice. Reading its artifact
(14988968394): the generated SRS line 35 was `|---|---|---|>` and REGISTER line 23 ended
without a closing pipe. Those are real defects, but the deterministic checks did not
name them. The judge reported them vaguely (it pointed at the wrong row), mixed in a
finding that its own text then called allowed (an INFERRED item at CLARIFY), and its
deliberation text ended up in the correction task. The correction model therefore had
no precise instruction.

## Decision
1. `a1_checks.table_format_errors`: every table row in SRS, REGISTER and VALIDATION must
   start and end with a pipe; each violation is reported with document, line number and the
   row tail. This ADDS a check; no existing check is removed or loosened. Earlier bundles
   (runs 17 to 21 artifacts) were scanned: only the run 21 bundle violates it.
2. The A1 judge instruction now says to report a defect only with the exact quoted text,
   item ID and the rule broken, to keep deliberation out of reasons, and not to list items
   the rule text allows. The pass/fail meaning and the standards are unchanged (E2 and
   the other checks are untouched).

## Consequences
- The correction attempt receives exact line-level feedback for the formatting class of
  failure. A bundle with a real defect still fails; a bundle without one is no longer
  failed on self-contradicting judge prose.
- Not a claim that run 21 would have passed: its defects were real and would still be
  rejected, now with precise messages.
