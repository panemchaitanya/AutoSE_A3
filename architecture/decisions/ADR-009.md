# ADR-009: Safety and failures - budgets in code, untrusted text in quarantine

- Status: Accepted
- Decision area: D9 (Safety and failures)

## Context

Anyone can write an issue, and issues are this workflow's input. A free-tier
API key has rate limits; runners die; stages get stuck. The system must fail
closed, cheap, and explained.

## Decision

**Budgets and limits (enforced by code, not prompts):**

- Per-stage agent step cap (40 tool actions) and job `timeout-minutes` (30).
- A token budget per issue run (default 1.5M tokens), tracked in
  `state.json` from API `usageMetadata`; crossing it stops the run with the
  reason recorded in the current stage's artifact.
- Fix loop max 3 cycles; review loop max 2 rounds (ADR-002).
- A stage that cannot pass its check writes *why* into its artifact and the
  run stops there - the table's required behavior, and the reason the
  artifacts matter for grading partial runs.
- Before the first run, the provider account's spend is capped by using a
  free-tier key with no billing attached; total tokens used are reported in
  `results/results.csv`.

**Prompt-injection posture (anyone can write an issue):**

- Issue and comment text is passed to agents only inside explicit delimiters
  with an instruction that the delimited text is data, never commands.
- The shell whitelist (ADR-005) contains no network, no `gh`, no `git push`:
  even a fully compromised agent turn cannot exfiltrate the secret or push.
- The API key exists only as an environment variable of the agent process;
  the harness never prints environment variables and redacts the key pattern
  from logs.
- Only the repo owner can trigger the workflow (ADR-010), which bounds who
  can spend the budget in the first place.

## Alternatives considered

- **Rely on model refusal training for injection.** Rejected as the only
  layer: refusals are probabilistic; the whitelist and the permission model
  are not.
- **Unlimited retries with backoff.** Rejected: a stuck stage burning a free
  daily quota looks exactly like a slow stage; caps make the failure legible.

## Consequences

- Worst case for a hostile or pathological issue: a bounded amount of free
  quota spent, a stopped run, and an artifact saying why.
- Every budget decision is visible and changeable in one place
  (`workflow/agent/config.py`), documented in the README.
