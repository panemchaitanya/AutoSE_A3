# ADR-006: Models - two tiers: a stronger flash for judgment, a lite flash for structure

- Status: Superseded by ADR-012
- Decision area: D6 (Models)

## Context

The assignment must run on a free-tier Gemini API key with daily quota and
per-minute rate limits. Stages differ in how much reasoning depth they need,
and in how costly a shallow answer is. A further constraint found while
testing: the 2.5-generation models are no longer served to this key, and the
pro-tier previews are outside the free quota, so the realistic tiers are the
3.x flash family.

## Decision

- **gemini-3.5-flash** for Developer and Reviewer: these two decide whether
  the code is right. A missed edge case here costs a whole fix cycle or a
  bad approval, which dwarfs the token saving.
- **gemini-3.5-flash-lite** for SpecWriter, Designer, Tester and the judge:
  their output is structured (a spec in my A1 ledger format, a design with a
  file list, tests against given criteria) and mechanically checked
  afterwards, so a fast cheap model plus a hard checker beats a slow model
  trusted blindly. The AI Studio rate-limit page for this project (free
  tier, no billing account) shows 3.5-flash-lite at 500 requests/day, while
  the other 3.x flash models it lists (3 Flash, 3.8 Flash) get only
  20/day; 3.5-flash itself is not listed there, so the run budget treats
  HTTP 429 with recorded fallback (below) as the enforcement mechanism
  rather than trusting a displayed number.
- Models are repo variables (`vars.MODEL_*`), not hard-coded, so a quota
  failure or a pricing change is a settings edit, not a commit.
- On HTTP 429 the harness backs off, then falls back one tier
  (3.5-flash -> 3.5-flash-lite) for that call and records the fallback in
  `usage.json` and the stage artifact. A run degraded this way is labeled in
  `results/results.csv`.

Total token usage per run is recorded from the API's `usageMetadata` and
reported in the results (brief's cost rule); the key sits in repository
secrets and appears in no prompt, log or artifact, and the project has no
billing attached - the free quota is the hard spend limit.

## Alternatives considered

- **Strongest available model everywhere.** Rejected: the free-tier pro
  previews are quota-blocked for this key (verified while testing), and
  spending the scarce tier on lint-shaped output wastes it.
- **Lite everywhere.** Rejected: implementation and review are where shallow
  reasoning ships broken diffs and rubber-stamp approvals; see experiment E1,
  which measures exactly this trade for the Developer role.
- **Different model providers per role for diversity.** Deferred: a single
  provider keeps the harness and secrets simple; reviewer independence comes
  from context isolation (ADR-008), not from brand diversity. Listed in the
  report's limitations.

## Consequences

- Cost per full issue run stays within free-tier daily quota for the 5
  required issues plus experiments, at the price of an occasional fallback.
- The two-tier split is itself a testable decision: E1 compares
  3.5-flash-lite vs 3.5-flash for the Developer on real issues
  (`experiment/variants.md`).
