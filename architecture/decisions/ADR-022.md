# ADR-022: Make the fallback model tier configurable in the hosted workflow

## Status

Accepted, 25 November 2026, 00:10 IST, late work. Extends ADR-006 (fallback tier)
and ADR-021. Nothing is superseded. Checks, budgets, correction bounds and retry
constants are unchanged.

## Context

`config.MODEL_FALLBACK` already reads the environment, but the hosted workflow
never passed it, so primary and fallback were both gemini-3.5-flash-lite and a
503 burst on that model had no alternate tier (runs 45442883647, 45449108458 and
45454572048 all ended in 503 on the single model). Probes at 00:00 IST on the
free key returned 200 for gemini-3-flash-preview and gemini-3.5-flash-lite and 503
for gemini-3.1-flash-lite, gemma-4-31b-it and gemini-flash-latest. One 200 is not
proof of capacity or of a separate quota.

## Decision

Pass MODEL_FALLBACK from the repo variable (default unchanged). Set the variable
to gemini-3-flash-preview for hosted runs after this merge. The fallback is still
used only after the primary exhausts its retries. Every call's model is recorded
in calls.jsonl, so a run that used the fallback is identifiable and is reported
as a different configuration from an all-flash-lite run.

## Alternatives

- Lower primary retries so the fallback engages sooner: changes the bound
  from ADR-021, left for a separate decision.
- Paid tier: not authorized.

## Consequences

If the fallback also returns 503 or 429, the stage fails closed as before. The
gain is unproven until a run records fallback calls.
