# ADR-008: Reviewer independence - separate workflow, fresh context, no push rights

- Status: Accepted
- Decision area: D8 (Reviewer independence)

## Context

A reviewer that watched the implementation will tend to approve it: it has
seen the intent, the spec the code was written against, and a stream of
confident intermediate claims. The brief requires a reviewer that does not
simply agree with the implementer.

## Decision

Independence is enforced in four independent places, so no single failure
breaks it:

1. **Separate workflow** (`autose-review.yml`) with a separate job and its
   own minimal permissions: `contents: read`, `pull-requests: write` (to post
   the review), **no `contents: write`** - the reviewer cannot push.
2. **Fresh context**: the reviewer is a new agent conversation. Its inputs
   are exactly the issue text, the PR diff, and the repo checked out at the
   PR head. It never receives `spec.md`, `design.md`, `test_report.md`, any
   agent log, or any reasoning from stages 1-5 (enforced by ADR-003's input
   declarations, not by politeness).
3. **Own prompt**: it is told to behave like a maintainer who did not write
   the code, must ground every finding in a file and line, and may run the
   code itself (read-only shell whitelist, tests included).
4. **Measured, not assumed**: five seeded PRs with planted defects
   (`experiment/seeded_prs/`) are reviewed by the same path, and the catch
   rate is reported. A reviewer that approves the seeded defects is caught
   by the experiment, not trusted. Experiment E2 additionally measures the
   catch rate with pipeline context leaked in, to show the isolation is
   doing the work.

## Alternatives considered

- **Same job, "be objective" prompt.** Rejected: instructions cannot remove
  information from a context that already contains it.
- **Different model provider for the reviewer.** Deferred (ADR-006): context
  isolation is the stronger guarantee and provider diversity costs a second
  secret and quota to manage; noted as future work.
- **Human-only review.** That is the brief's baseline, not an agentic design;
  the human still owns the merge decision after the agent review.

## Consequences

- The reviewer can only *comment* on the PR; the merge stays human (Rules:
  never merge).
- The seeded-PR catch rate is a standing regression test for the reviewer's
  independence: if a prompt or model change drops it, that shows up in the
  numbers, not in a vibe.

## Student discussion and course constraint, 2026-11-23

Chaitanya's view is that a coder's explanation can add useful weight, but a
reviewer should challenge it rather than follow it blindly, prioritizing
correctness and efficiency. This is a tradeoff, not his endorsement of
hiding explanations. The assignment explicitly excludes implementer
reasoning from the required review, so the submission follows that input
boundary under his instruction to comply with the rules. No optional
explanation-sharing feature is added for this deadline. Local E2 informs
the anchoring risk but is not proof of hosted reviewer isolation.
