# ADR-028: Unique execution branch per run (suffix)

Status: accepted (post-disclosure, after run 21). Harness identity changes from ADR-027.

## Context
The gate always used `autose/issue-N`. A rerun on an issue therefore had to rewrite an
older bot branch (archive the old tip, then force-with-lease). Run 19 failed on that lease
push with the git error hidden. The maintainers asked that reruns leave older branches and
their residue untouched.

## Decision
`gate.branch_for(issue, explicit, suffix)`:
- default `autose/issue-N` (unchanged);
- repository variable `AUTOSE_BRANCH_SUFFIX=<alnum>` selects `autose/issue-N-<suffix>`, a
  new branch, so no existing ref is rewritten;
- a continuation dispatch passes the branch explicitly; the gate accepts it only if it
  belongs to the same issue (`autose/issue-N` or `autose/issue-N-<alnum>`).
The branch is propagated end to end: gate output, all stage checkouts, the release PR head,
the review workflow (input `branch`, used to locate the PR) and the review-triggered
continuation dispatch. Artifacts and state.json already record the branch.

## Consequences
- Old branches, archive refs and tags stay exactly as they are; nothing is deleted or
  force-updated.
- No check, limit or model setting changes. Runs from here are reported as the ADR-028
  harness configuration, separate from runs 14 to 21.
- If the suffix variable is changed between a release and a review round, the explicit
  branch input keeps the continuation on the right branch.

## Tests
`workflow/tests/test_branch_suffix.py`: default, suffix, explicit-wins, rejection of other
issues' branches and unsafe suffixes, and propagation strings in both workflows.
