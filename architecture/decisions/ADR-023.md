# ADR-023: State the VALIDATION format the stage validator checks, in the SpecWriter prompt

## Status

Accepted, 25 November 2026, 01:55 IST, late work. Extends ADR-020 (A3 reuse
profile). Nothing superseded. No check, bound, correction attempt count or model
changes.

## Context

Run 45470790181 (#37), the first fresh-series run past the SpecWriter's first
output, failed attempt 1 of the A1 validation with: VALIDATION missing required
topic "gate"; no explicit PASS/FAIL/N/A for T2, T3, E2, E3, E4; and a basis/gate
contradiction (NFR-001 INFERRED but READY). The correction attempt then ended in
a provider 503 on both tiers. The validator (a1_checks.py) requires the words
verdict, gate, basis, tool, human, a readiness verdict, and one result line per
21 check IDs. The prompt only says "Validation PASS claims must match the actual
rows" and the model keeps just the last four action pairs, so these mechanical
requirements are easy to drop.

## Decision

Add one paragraph to SPEC_SYSTEM listing exactly what the validator reads: the
five topic words, the verdict forms, the 21 check IDs and the INFERRED/ASSUMED not
READY rule. Validator, correction bound (2 attempts) and all checks are unchanged.

## Alternatives

- Loosen the validator: rejected, that would hide real A1 failures.
- Raise correction attempts: changes a bound, not needed to fix an omission.

## Consequences

New harness identity from this merge (prompt revision). Evidence so far is one
failed first attempt, so the effect is unproven; results are reported as a
separate configuration from runs before it.
