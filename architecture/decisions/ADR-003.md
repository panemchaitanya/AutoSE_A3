# ADR-003: Hand-offs - typed artifacts, minimal inputs per agent

- Status: Accepted with implementation limitations recorded below
- Decision area: D3 (Hand-offs)

## Context

What an agent is allowed to see decides what it can be influenced by. Passing
"everything so far" is easy and wrong: it propagates early mistakes, leaks the
implementer's reasoning into the reviewer, and inflates every prompt.

## Decision

Agents receive **only the declared inputs for their stage** (see
`architecture/views/stage-map.md` for the full table):

- SpecWriter: the issue text. Not the repo.
- Designer: `spec.md`, my A2 `ARCHITECTURE.md`, and the repo file tree.
  Not the issue's raw wording.
- Developer: `design.md`, the spec's acceptance criteria, and read/write file
  tools on a repo checkout.
- Tester: the spec's acceptance criteria, `diff.patch`, and the repo. It
  writes its own tests; it never sees hidden acceptance tests.
- Reviewer: the issue text, the PR diff, and the repo checked out at the PR
  head. **Never** `spec.md`, `design.md`, `test_report.md`, agent logs, or
  any conversation from stages 1-4.

Hand-offs are whole artifacts (full documents), not summaries - the documents
are small, and summarization is where fidelity dies. The exception is the
reviewer, whose exclusion list matters more than its reading list.

## Alternatives considered

- **Full shared context / chat transcript between agents.** Rejected: the
  reviewer would see the implementer's intent and anchor on it (ADR-008), and
  every stage would pay for every earlier stage's tokens.
- **Summaries between stages.** Rejected: a summary is a lossy rewrite by the
  same model family that made the content; passing the artifact itself keeps
  one source of truth per stage.
- **Repo access for everyone.** Rejected for SpecWriter and Reviewer: the spec
  should describe the need, not the convenient change; the reviewer should
  judge the change as a maintainer would, from the issue and the code.

## Consequences

- Context isolation is testable, and I test it: experiment E2 seeds PRs with
  known defects and measures the reviewer's catch rate with and without
  pipeline context (see `experiment/variants.md`).
- If a stage needs information it was not given, the correct fix is to change
  the declared inputs in the stage map and this ADR, not to smuggle data into
  a prompt.

## Implementation audit, 2026-11-23

The list above is the intended prompt hand-off, not a filesystem access
control. SpecWriter and other pre-review roles currently have repository
file tools, so saying SpecWriter cannot see the repo would be false. The
corrected Reviewer uses a filtered diff and clean copy excluding pipeline
artifacts, experiment labels and git history. Early runs did not implement
that filter. Python shell capability is still not a sandbox (ADR-013).
Local E2 measured one model and authored stimuli; it does not validate every
hosted role's access boundary. The grader's required reviewer-input rule
remains the design target, not the student's preferred explanation policy.
