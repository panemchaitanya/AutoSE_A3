# ADR-011: Serialize workflows against the shared provider quota

- Status: Accepted, hosted continuation under validation
- Supersedes: ADR-010 concurrency choice; owner-trigger rules retained
- Decision area: D10, D9

## Context

Parallel issues used separate branches correctly but shared one Gemini free
project. Runs 45177088477, 45177093956 and 45177100090 returned HTTP 429 with
a reported 15 requests/minute limit. Branch isolation did not isolate API
capacity. Earlier flash Developer calls also timed out.

## Decision

Use a repository-wide Actions concurrency group and client pacing of at
least five seconds between requests. Keep owner label/comment checks and
GitHub write-authorized manual dispatch. Continue one issue at a time.
Retries are bounded and transport failures are distinct from rate limits.

## Alternatives

More parallel runs: rejected because they share the measured rate bucket.
Paid quota: not authorized. Another free project: optional, not necessary
until the serial route is tested, and not a substitute for correct pacing.

## Consequences

Lower throughput, less self-inflicted throttling. Multiple repositories or
external clients could still share the same project quota, so this is not a
cross-account rate limiter. GitHub concurrency is not a FIFO guarantee;
launch one continuation at a time rather than stacking pending runs.
