# ADR-024: A requirements correction attempt must change a file before it can finish

## Status

Accepted, 25 November 2026, 02:35 IST, late work. Extends ADR-020 and ADR-023.
Nothing superseded. The validator, the two-attempt correction bound, models and
every stage check are unchanged.

## Context

Run 45479843730 (#37) failed Stage 1 on content. Attempt 1 failed A1 validation
(VALIDATION lacks the topic "gate", NFR-001 INFERRED but READY). The correction
task named these defects and told the agent to edit the failing documents. The
correction transcript (artifact transcript_requirements_attempt2_...json) shows 6
actions: git status, find, cat the SRS, read VALIDATION, read REGISTER, then
finish. No write_file or edit_file happened, so attempt 2 re-submitted the same
files and failed with the same errors, consuming the last correction attempt. The
Developer role already rejects a finish that has no source diff; the SpecWriter
correction had no equivalent.

## Decision

In a SpecWriter correction run (task contains "failed its checks"), reject a
finish action until the agent has issued write_file, edit_file or a python shell
command, and tell it why. It stays inside the existing step cap, so the bound is
unchanged. The validator still decides pass or fail.

## Alternatives

- Add a third correction attempt: changes a bound, not needed to fix this gap.
- Loosen the validator: rejected.

## Consequences

New harness identity from this merge. Effect unproven (one observed case). Two unit
tests cover a rejected finish followed by an accepted edit, and an unaffected
first attempt.
