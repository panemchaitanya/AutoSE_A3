# ADR-013: Treat the command filter as a convenience, not a sandbox

- Status: Accepted limitation; hardened isolation remains future work
- Supersedes: ADR-005 permission claims and ADR-009 injection guarantees
- Decision area: D5, D9

## Context

The initial ADRs overstated what a prefix whitelist enforces. Python and
shell execution allow arbitrary operations. Direct write_file restrictions
do not constrain Python writes. No claim that a compromised model cannot
access secrets, network, or Git credentials is supported by this design.

## Decision

Keep the small JSON interface and direct-path checks for this scoped course
prototype, but do not describe them as a security boundary. Treat issue text
as untrusted; keep owner trigger checks, bounded loops, stripped shell env,
read-only reviewer token, and clean reviewer inputs as distinct mitigations.
No hostile-input deployment claim is made. Full isolation needs a container
or process sandbox, filesystem/network restrictions and separate credentials.

## Alternatives

Rely on prompts or delimiters: insufficient. Claim safety from allowed
command names: false while Python and shell execution remain available.

## Consequences

This is a material limitation against the brief's least-privilege goal.
A provider token limit is checked before calls and may overshoot by the
final response. Usage from crashed attempts may be missing. Job timeouts and
step/loop caps bound ordinary failures, not adversarial code execution.
