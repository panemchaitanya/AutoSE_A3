# ADR-030: Factual Developer feedback for no-op edits and a still-empty source diff

Status: proposed (post-disclosure, after run 22). Merge only between runs.

## Context
Run 22 (45541620577, #39) failed develop with "step cap 40 reached" (artifact 14989977257).
The Developer read tinydb/table.py about 30 times, made one edit whose old_text equalled
new_text, tried to finish at step 19 and was rejected ("Finish rejected: no actual source
diff exists", agent.py), then kept reading until the cap. Two harness facts misled it: the
no-op edit was recorded as "applied" in the action ledger, and the only hint was a generic
"avoid rereading" line.

## Decision
1. `edit_file` with old_text equal to new_text now returns an ERROR saying nothing was
   modified (the ledger therefore records an error, not "applied").
2. For the Developer from step 12, if `git diff origin/main -- tinydb` is empty, the
   per-step action-index message adds one factual sentence: no source change exists yet,
   N steps remain, edit now.
Nothing else changes: MAX_AGENT_STEPS stays 40, the finish rejection rule, the tests and
every stage check are untouched. Feedback is information, not a relaxed limit.

## Consequences
- A model that loops on reads gets an accurate signal sooner. It can still fail honestly
  at the cap; this is not a claim that develop will pass.
- agent.py is part of the harness identity, so this is a new configuration (after run 23).

## Tests
`workflow/tests/test_developer_feedback.py`: no-op edit reports no change and leaves the file
unchanged; the empty-diff note appears from step 12 only while the diff is empty and
disappears after a real edit. Full suite: 104 passed.
