# ADR-001: Splitting the work - five specialist agents plus a scripted release

- Status: Accepted
- Decision area: D1 (Splitting the work)

## Context

The pipeline has six stages with very different cognitive shapes: requirements
writing, design, code editing, test writing, mechanical publishing, and
independent review. A single agent doing all of them carries one ever-growing
context, grades its own homework, and makes the reviewer meaningless. One
agent per stage is the other extreme: some stages need no judgment at all.

## Decision

Five LLM agent roles, one per judgment stage - SpecWriter (requirements),
Designer (design), Developer (implementation), Tester (testing), Reviewer
(review) - and **no agent for release**, which is a scripted sequence of
`gh` commands. Developer and Tester are separate roles but run inside one
job so the fix loop does not pay for a new Actions run per cycle.

## Alternatives considered

- **One agent for everything.** Rejected: the reviewer's independence (ADR-008)
  becomes impossible inside one context, prompts become huge, and a weak stage
  contaminates the next one with no checkpoint in between.
- **One agent per stage including release.** Rejected: release is push + open
  PR + write a link file. An LLM adds cost and failure modes (wrong base
  branch, leaked tokens in a hallucinated command) where determinism is free.
- **Developer and Tester merged.** Rejected: the tester writes tests from the
  spec, not from the diff's intent; merging them lets the implementer define
  what "correct" means. Keeping them separate keeps stage 4's check honest.

## Consequences

- Each agent prompt is short and each context small, which keeps token cost
  and rate-limit pressure low (see ADR-006, ADR-009).
- Every agent boundary coincides with an artifact boundary, so the controller
  can checkpoint, resume and audit between agents (ADR-004).
- Two more prompts to maintain than the minimal design; that is the price of
  separation of concerns.
