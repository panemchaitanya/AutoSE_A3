# ADR-034: Structured table output, rendered by the harness (amends ADR-005 tool contract)

Status: proposed (post-disclosure). Merge only between runs; runs after it are a different configuration.

## Context
Runs 21 to 26: the SpecWriter's raw model reply itself contains malformed markdown table
rows (for example `|---|---|---| p`); the write tool stores content unchanged (run 24
transcript). Telling the model the exact error (ADR-029, ADR-031, ADR-032) did not stop it
on first attempts. The defect is a representation problem: asking a small model to hand-type
pipes and dash cells.

## Decision
`write_file` may carry `tables: [{name, header[], rows[][]}]` and the content marks each
position with a line `{{TABLE:name}}`. The harness formats the markdown table (fixed separator
row, pipe escaping, whitespace collapsed inside cells). It never invents, drops or rewords a
cell. A row whose cell count differs from the header, a placeholder without data, or data
without a placeholder returns an ERROR observation and writes nothing, so the model must fix
its own data. Raw markdown tables stay allowed and are still checked by ADR-029/032.
No semantic check, judge, limit or step cap changes; the A1 and judge checks run on the
rendered file exactly as before. This is not auto-repair of bad output: content is the model's.

## Validation
Offline tests in `test_render_tables.py`: rendering passes `table_format_errors`; cell-count
mismatch writes nothing; content like "TBD" is preserved (the testability judge still sees it).
Full suite: 113 pass.

## Consequences
Removes one mechanical failure class if the model uses the option. Not a pass claim.
